\section{Definition and Motivations}

\textbf{Information Retrieval} (IR) is the scientific and engineering discipline concerned with representing, storing, organizing, and accessing large collections of predominantly unstructured or semi-structured data to satisfy an \textbf{information need} expressed by a user~\cite{manning2008,buttcher2010}.

\begin{definition}[Information Retrieval (Manning et al.)]
Information Retrieval is finding material of an unstructured nature (usually text) that satisfies an information need from within large collections stored on computers.
\end{definition}

In the modern digital landscape, Information Retrieval extends far beyond general-purpose Web search engines (such as Google or Bing) to serve as the foundational infrastructure for:
\begin{itemize}
    \item \textbf{E-commerce and marketplaces:} product retrieval driven by textual descriptions, structured specifications, and customer reviews (e.g., Amazon, Alibaba, eBay).
    \item \textbf{Enterprise and Desktop Search:} indexing and semantic searching across enterprise repositories (documents, emails, source code bases).
    \item \textbf{RAG (\textit{Retrieval-Augmented Generation}) Systems:} grounding Large Language Models (LLMs) with external, authoritative context documents to eliminate hallucinations and supply real-time fresh knowledge.
    \item \textbf{Autonomous agents and recommender engines:} content-based and collaborative filtering for personalized content discovery and media streaming (e.g., Netflix, Spotify, Meta, Pinterest).
\end{itemize}

\subsection{The Generative Shift: From Web Search to Agentic Search}

The rise of conversational Large Language Models (LLMs) has not diminished the relevance of Information Retrieval; rather, it has placed IR at the center of modern AI systems. An interview with an LLM reveals that conversational AI fundamentally depends on core IR competencies:
\begin{enumerate}
    \item \textbf{Semantic Query Understanding:} advanced natural language processing (NLP) to parse and disambiguate user intent.
    \item \textbf{Matching and Relevance Scoring:} identifying and prioritizing the most pertinent information across massive corpora.
    \item \textbf{Contextual Retrieval for Fresh Information:} pure generative models are bound by their training cutoff and cannot answer questions requiring recent or private knowledge without expensive retraining.
\end{enumerate}

To bridge this gap, modern architectures rely on \textbf{RAG (\textit{Retrieval-Augmented Generation})}: the system extracts queries from user input, retrieves authoritative passages from an external corpus or the Web, and injects them into the LLM's prompt context to synthesize an accurate, cited response without modifying model parameters.

\subsubsection{Agentic Search and the Adaptive Feedback Loop}
While conventional RAG operates as a single-step pipeline (query $\to$ retrieve $\to$ generate), complex inquiries necessitate \textbf{Agentic Search}:

\begin{definition}[Agentic Search]
\textbf{Agentic Search} is an autonomous, multi-turn retrieval process in which an AI agent dynamically decides subsequent search actions based on intermediate findings. The agent inspects retrieved sources, identifies missing knowledge or discrepancies (\textit{information gaps}), formulates targeted follow-up queries, and iterates until sufficient evidence is assembled to synthesize the final answer.
\end{definition}

\begin{alertblock}{Relevance: The Core of IR}
While database systems evaluate binary truth against relational predicates, Information Retrieval focuses on estimating the degree of \textbf{relevance} of each document with respect to the user's underlying cognitive information need. Relevance is inherently subjective, context-dependent, and time-varying.
\end{alertblock}

\section{The Two Fundamental Goals: Effectiveness and Efficiency}

A large-scale information retrieval system must simultaneously optimize two competing objectives:
\begin{enumerate}
    \item \textbf{Effectiveness:} Quantifies the intrinsic quality of the returned results, assessing how well the ranked list satisfies the user's search intent (thoroughly addressed in Chapter~\ref{chap:evaluation}).
    \item \textbf{Efficiency:} Quantifies computational cost, throughput (queries processed per second), and latency (demanded within $10$--$50$ milliseconds per query across billions of documents).
\end{enumerate}

\subsection{Efficiency and Underlying Hardware Architecture}
The efficiency of a modern search engine depends not merely on algorithmic complexity, but on hardware execution dynamics:
\begin{itemize}
    \item \textbf{Pipelining and Superscalar Processors:} Modern CPUs segment instruction execution into sequential stages (Instruction Fetch, Decode, Execute, Memory Access, Write Back), issuing multiple instructions per clock cycle.
    \item \textbf{Pipeline Hazards:}
    \begin{itemize}
        \item \textit{Structural Hazards:} Resource contention when multiple instructions compete for the same execution unit or memory bus.
        \item \textit{Data Hazards:} Logical data dependencies between consecutive instructions (RAW: Read-After-Write), forcing pipeline stalls (\textit{bubbles}) when values are unavailable.
        \item \textit{Control Hazards:} Branch mispredictions. During posting list intersection loops, an incorrect branch prediction flushes the pipeline, incurring a penalty of $15$--$20$ clock cycles per misprediction.
    \end{itemize}
    \item \textbf{Memory Hierarchy:} CPU registers operate at sub-nanosecond speeds, L1/L2/L3 caches respond in a few clock cycles, whereas main memory (RAM) requires $50$--$100$ ns and secondary storage (NVMe/SSD) demands tens of microseconds. Posting list layouts prioritize sequential, contiguous memory layouts to maximize cache-line reuse and trigger hardware prefetching.
    \item \textbf{SIMD (\textit{Single Instruction Multiple Data}) Vectorization:} Utilizing 128-bit, 256-bit, or 512-bit vector registers (AVX-2, AVX-512, ARM NEON) enables simultaneous comparisons of 8 or 16 document identifiers in a single machine cycle, dramatically accelerating posting intersections.
    \item \textbf{Parallel Computing and Distributed Sharding:} Indices exceeding the capacity of a single machine are partitioned (\textit{sharded}), typically through document-level sharding, allowing compute clusters to process queries concurrently with centralized result aggregation.
\end{itemize}

\subsection{Text Processing Pipeline}
Raw textual content undergoes four sequential preparation stages:
\begin{enumerate}
    \item \textbf{Tokenization:} Decomposing character streams into lexical tokens, handling punctuation, special characters, and hyphenated terms.
    \item \textbf{Normalization and Case Folding:} Converting tokens to lowercase and stripping accents/diacritics to ensure uniformity across queries and documents.
    \item \textbf{Stopword Filtering:} Removing high-frequency functional words with minimal discriminative value (e.g., \texttt{"the"}, \texttt{"is"}, \texttt{"at"}, \texttt{"which"}).
    \item \textbf{Stemming and Lemmatization:}
    \begin{itemize}
        \item \textit{Stemming:} Algorithmic stripping of suffixes using heuristic rules (such as Porter's algorithm~\cite{manning2008}) to extract the root form (\textit{stem}). Example: \texttt{"retrieving"}, \texttt{"retrieval"} $\to$ \texttt{"retriev"}.
        \item \textit{Lemmatization:} Full grammatical analysis utilizing vocabulary dictionaries to map inflected forms to their formal base lemma. Example: \texttt{"am"}, \texttt{"were"} $\to$ \texttt{"be"}.
    \end{itemize}
\end{enumerate}

\section{Language Properties and Retrieval Models}

Natural language word distributions adhere to statistical empirical laws that shape index designs and ranking algorithms:
\begin{itemize}
    \item \textbf{Zipf's Law:} The frequency $f(r)$ of a term is inversely proportional to its frequency rank $r$:
    \begin{equation}
    f(r) \propto \frac{1}{r}
    \end{equation}
    A handful of words dominate overall occurrences, while the vast majority of words appear extremely rarely (\textit{long tail}).
    \item \textbf{Heaps' Law:} The vocabulary size $|V|$ grows as a power law with respect to collection size in terms of total word tokens $N$:
    \begin{equation}
    |V| = k \cdot N^\beta \quad (\text{with } 0.4 \le \beta \le 0.6)
    \end{equation}
    The vocabulary never fully saturates as more documents are gathered.
\end{itemize}

Core retrieval models include:
\begin{enumerate}
    \item \textbf{Boolean Model:} Deterministic matching against logical operators ($\land, \lor, \neg$), lacking an intrinsic relevance score.
    \item \textbf{Vector Space Model (TF-IDF):} Documents and queries are modeled as vectors across vocabulary space $|V|$, weighted by term frequency ($TF$) and inverse document frequency ($IDF$), scored via cosine similarity.
    \item \textbf{Probabilistic Model (BM25):} The de facto industry standard for lexical retrieval based on the 2-Poisson probabilistic model~\cite{buttcher2010}. It formalizes asymptotic term frequency saturation and penalizes excessively long documents to mitigate verbosity bias:
    \begin{equation}
    \operatorname{score}_{\text{BM25}}(q, d) = \sum_{t \in q} \operatorname{IDF}(t) \cdot \frac{tf(t, d) \cdot (k_1 + 1)}{tf(t, d) + k_1 \cdot \left(1 - b + b \cdot \dfrac{|d|}{\text{avgdl}}\right)}
    \label{eq:bm25-formula-en}
    \end{equation}
    where:
    \begin{itemize}
        \item $\operatorname{IDF}(t) = \ln \left( \dfrac{N - df_t + 0.5}{df_t + 0.5} + 1 \right)$ quantifies the informative specificity of term $t$ across the entire collection of $N$ documents.
        \item $tf(t, d)$ is the raw term frequency of $t$ within document $d$.
        \item $k_1 \ge 0$ (term frequency saturation parameter, typically calibrated between $1.2$ and $2.0$): governs how rapidly repeated occurrences of the same term flatten toward an asymptote.
        \item $b \in [0, 1]$ (document length normalization penalty, typically $b \approx 0.75$): regulates the penalty applied to document length $|d|$ relative to the average collection document length $\text{avgdl}$. At $b=1$, the penalty for lengthy documents is maximal; at $b=0$, document length is entirely ignored.
    \end{itemize}
\end{enumerate}

\section{The Inverted Index}

The \textbf{Inverted Index} reverses document storage directionality, establishing a mapping $t \mapsto \mathcal{P}_t$, where $\mathcal{P}_t$ is the ordered list of documents containing term $t$~\cite{manning2008}.

\begin{definition}[Inverted Index]
An Inverted Index consists of two complementary components:
\begin{enumerate}
    \item \textbf{Dictionary (Vocabulary):} Stores all unique terms appearing across the collection, maintained via fast lookup structures (B-Trees or Hash Tables), along with document frequency $df_t$ and a pointer to the start of its posting list.
    \item \textbf{Posting List:} For each term $t$, an ordered array of document identifiers sorted strictly in ascending order ($\text{DocID}_1 < \text{DocID}_2 < \dots$). Each posting may also record auxiliary metadata such as local term frequencies ($tf$) and intra-document term position offsets.
\end{enumerate}
\end{definition}

\subsection{Query Processing and Merge Algorithms}
The strictly ascending order of DocIDs enables Boolean and phrase queries to be evaluated via coordinated traversals of posting lists:
\begin{itemize}
    \item \textbf{Conjunctive Query (AND):} Identifies documents containing all specified terms simultaneously. For example, evaluating $q = \text{\texttt{"inverted" AND "index"}}$:
    \[
    \mathcal{P}_{\text{inverted}} \cap \mathcal{P}_{\text{index}} = [1, 2] \cap [1, 2] = [1, 2] \implies \{d_1, d_2\}
    \]
    Conversely, for $q = \text{\texttt{"query" AND "inverted" AND "index"}}$:
    \[
    (\mathcal{P}_{\text{inverted}} \cap \mathcal{P}_{\text{index}}) \cap \mathcal{P}_{\text{query}} = [1, 2] \cap [3] = \emptyset
    \]
    The two-pointer intersection merge (Algorithm~\ref{alg:merge-intersection-en}) provides linear complexity $\BigO{|P_1| + |P_2|}$. When evaluating queries with $k > 2$ terms, best practice dictates processing posting lists in ascending order of document frequency $df_t$, starting with the shortest list to minimize intermediate candidate sets.
    \item \textbf{Disjunctive Query (OR):} Identifies documents containing at least one of the query terms. For $q = \text{\texttt{"query" OR "inverted"}}$:
    \[
    \mathcal{P}_{\text{query}} \cup \mathcal{P}_{\text{inverted}} = [3] \cup [1, 2] = [1, 2, 3] \implies \{d_1, d_2, d_3\}
    \]
    \item \textbf{Phrase Search:} To match exact sequences of words (e.g., \texttt{"inverted index"}), posting lists store positional offsets for each occurrence within a document. The evaluation algorithm verifies that:
    \[
    \text{pos}(\text{index}) - \text{pos}(\text{inverted}) = 1
    \]
    filtering out documents where terms appear in reversed order or at non-adjacent positions.
\end{itemize}

\begin{algorithm}[H]
\caption{Merge Intersection for Conjunctive Queries ($P_1 \land P_2$)}
\label{alg:merge-intersection-en}
\KwInput{Two sorted posting lists $P_1$ and $P_2$}
\KwOutput{Sorted list $R$ containing DocIDs present in both lists}
$R \leftarrow \emptyset$\;
$i \leftarrow 1$; $j \leftarrow 1$\;
\While{$i \le |P_1|$ \textbf{and} $j \le |P_2|$}{
    \If{$P_1[i] == P_2[j]$}{
        $R.\text{append}(P_1[i])$\;
        $i \leftarrow i + 1$\;
        $j \leftarrow j + 1$\;
    }
    \ElseIf{$P_1[i] < P_2[j]$}{
        $i \leftarrow i + 1$\;
    }
    \Else{
        $j \leftarrow j + 1$\;
    }
}
\Return{$R$}\;
\end{algorithm}

\section{Index Compression Techniques}

Compressing inverted indices serves two goals: minimizing storage footprint and converting slow I/O bus transfer bottlenecks into fast CPU decompression operations.

\subsection{Binary Interpolative Coding}
\textbf{Binary Interpolative Coding} (introduced by Moffat and Stuiver~\cite{moffat2000}) is a specialized compression algorithm tailored for strictly monotonically increasing integer sequences.

\begin{definition}[Interpolative Coding Principle]
Given a sorted sub-sequence of $n$ integers $L = [x_1, x_2, \dots, x_n]$ bounded in the interval $[l, h]$ (such that $l \le x_1 < x_2 < \dots < x_n \le h$), the algorithm selects the median element $m = \lfloor (n+1)/2 \rfloor$.
Because there must be at least $m - 1$ distinct integers preceding $x_m$ and at least $n - m$ distinct integers following it, $x_m$ is restricted to the interval:
\begin{equation}
l + m - 1 \le x_m \le h - n + m
\end{equation}
The number of valid candidate values for $x_m$ is:
\begin{equation}
R = (h - n + m) - (l + m - 1) + 1 = h - l - n + 1
\end{equation}
The shifted value $(x_m - (l + m - 1))$ is encoded using exactly $\lceil \log_2 R \rceil$ bits. The procedure then recurses on the left sub-array over $[l, x_m - 1]$ and on the right sub-array over $[x_m + 1, h]$.
\end{definition}

\begin{example}[Recursive Decomposition Tree]
Consider the sorted posting list of $n = 12$ identifiers bounded in the interval $[0, 62]$:
\[
L = [3, 4, 7, 13, 14, 15, 21, 25, 36, 38, 54, 62] \quad (n=12, m=6, l=0, h=62)
\]
The recursive decomposition tree (Figure~\ref{fig:interpolative-tree-en}) partitions the sequence hierarchically:
\begin{itemize}
    \item The median element $x_6 = 15$ splits the sequence into left sublist $[3, 4, 7, 13, 14]$ constrained by $(n=5, m=3, l=0, h=14)$ and right sublist $[21, 25, 36, 38, 54]$ constrained by $(n=5, m=3, l=16, h=62)$.
    \item At the next lower level, the first sublist splits into $[3, 4]$ with $(n=2, m=1, l=0, h=6)$ and $[13, 14]$ with $(n=2, m=1, l=8, h=14)$.
    \item The leaf nodes encode individual elements: for instance, for $[14]$ with parameters $(n=1, m=1, l=14, h=14)$, the candidate range of valid values collapses to:
    \[
    R = 14 - 14 - 1 + 1 = 1 \implies \lceil \log_2 1 \rceil = 0 \text{ bits!}
    \]
\end{itemize}
When document identifiers form dense clusters, the candidate range $R$ collapses to $1$, reducing the storage footprint to zero bits for many clustered postings.
\end{example}

\subsection{Dictionary-Based Compression: LZ77}
For general text or token streams, the \textbf{Lempel-Ziv '77} (LZ77) algorithm maintains a sliding window comprising a Search Buffer and a Lookahead Buffer, emitting triples formatted as $(\text{offset}, \text{length}, \text{next\_char})$.

Consider the phrase segmentation of the sample input sequence:
\[
T = \underbrace{\text{\texttt{a}}}_{(0, \text{'a'})} \; \underbrace{\text{\texttt{b}}}_{(0, \text{'b'})} \; \underbrace{\text{\texttt{a b a}}}_{(2, 3)} \; \underbrace{\text{\texttt{a a a}}}_{(1, 3)} \; \underbrace{\text{\texttt{b a b a a a a b}}}_{(7, 8)}
\]
The resulting sequence of emitted pointers is:
\[
(0, \text{\texttt{'a'}}), \; (0, \text{\texttt{'b'}}), \; (2, 3), \; (1, 3), \; (7, 8)
\]
In this manner, long lexical repetitions are replaced with compact backward references within the sliding window. This algorithmic family forms the core of widely used production compressors such as \texttt{gzip}, \texttt{7-Zip}, and \texttt{LZ4} for high-throughput compressed storage.

\section{Learning-to-Rank (LTR) and the Non-Differentiability Challenge}

Within the architecture of a modern search engine (cf. Figure~\ref{fig:ir-architecture-detailed-en}), the candidate documents retrieved by the Inverted Index are passed to a machine learning re-ranking stage known as \textbf{Learning-to-Rank} (LTR)~\cite{burges2010}.

\subsection{Formulation of the Ranking Problem}
In the supervised LTR setting, the training collection consists of a set of queries, each paired with a list of candidate documents evaluated by human assessors or derived from implicit click logs:
\begin{equation}
\mathcal{T} = \left\{ \left( q, \langle (d_1, y_1), (d_2, y_2), \dots, (d_m, y_m) \rangle \right) \right\}
\end{equation}
where $y_i \in \{0, 1, 2, 3, 4\}$ denotes the graded relevance judgment on a multi-level ordinal scale:
\begin{itemize}
    \item $y = 0$: Irrelevant;
    \item $y = 1$: Marginally relevant;
    \item $y = 2$: Relevant;
    \item $y = 3$: Highly relevant;
    \item $y = 4$: Perfectly relevant.
\end{itemize}

Given a feature vector extracted for each query-document pair $\vec{x}_{q, d} = \Phi(q, d)$, a machine learning model computes a predicted relevance score $s_i = f_\theta(\vec{x}_{q, d_i})$. The final ranked list presented to the user is generated by sorting the documents in descending order of predicted score:
\begin{equation}
\pi = \operatorname{sort}_{\downarrow} \left( \{ (d_i, s_i) \}_{i=1}^m \right)
\end{equation}

\subsection{The Theoretical Challenge: Non-Differentiability of Ranking}
In standard regression problems, an algorithm minimizes mean squared error $\sum_i (f_\theta(x_i) - y_i)^2$. In Information Retrieval, however, a foundational principle applies:
\begin{alertblock}{The Core Principle of LTR}
\textbf{The goal is to learn the ranking, not the label}: the primary objective is not accurately predicting an isolated numerical label $y$, but optimizing the relative ordering of documents in the list presented to the user, maximizing evaluation metrics such as \textbf{NDCG} (\textit{Normalized Discounted Cumulative Gain}) or \textbf{MAP} (\textit{Mean Average Precision}).
\end{alertblock}

This formulation introduces a fundamental mathematical obstacle:
\begin{itemize}
    \item Ranking metrics $\mathcal{M}(\pi)$ depend directly on the \textbf{discrete ranks} (positions $1, 2, \dots, k$) assigned to each document by the sorting permutation.
    \item The sorting operation ($\operatorname{sort}$) is a piecewise constant, discontinuous step function.
    \item As model parameters $\theta$ vary smoothly, document positions remain invariant (derivative is exactly zero) until two scores cross, creating a step discontinuity (derivative is undefined):
    \begin{equation}
    \frac{\partial \mathcal{M}_{\text{NDCG}}(\pi_\theta)}{\partial \theta} = 0 \quad \text{almost everywhere (a.e.)}
    \end{equation}
    \item Consequently, \textbf{standard stochastic gradient descent (SGD) and backpropagation cannot be applied directly} to optimize official ranking metrics!
\end{itemize}

\subsection{LTR Model Families and Surrogate Gradients}
To circumvent the non-differentiability barrier, the literature has established three primary methodologies:
\begin{enumerate}
    \item \textbf{Pointwise Approach:} Treats each document as an independent regression or ordinal classification instance. While standard SGD applies directly, this method fails to model the inherently relative, competitive nature of ranked lists.
    \item \textbf{Pairwise Approach (e.g., RankNet):} Considers pairs of documents $(d_i, d_j)$ for the same query with differing relevance ($y_i > y_j$). The objective becomes minimizing inverted pairs, modeling the probability that $d_i$ outranks $d_j$ via a smooth logistic sigmoid:
    \[
    P(d_i \succ d_j) = \frac{1}{1 + e^{-\sigma (s_i - s_j)}}
    \]
    The cross-entropy loss over these probabilities is smooth and differentiable.
    \item \textbf{Listwise Approach and $\lambda$-Gradients (LambdaMART):} Directly optimizes the entire ranked list. \textbf{LambdaRank} introduces virtual surrogate gradients ($\lambda_{ij}$), defined by weighting pairwise gradients by the absolute metric change $|\Delta \operatorname{NDCG}_{ij}|$ resulting from swapping positions between $d_i$ and $d_j$:
    \begin{equation}
    \lambda_{ij} = \frac{-\sigma}{1 + e^{\sigma(s_i - s_j)}} \cdot |\Delta \operatorname{NDCG}_{ij}|
    \end{equation}
    Combining these virtual gradients with Gradient Boosted Decision Trees produced \textbf{LambdaMART}~\cite{burges2010}, which remained the industry gold standard in web search engines for over a decade.
\end{enumerate}

\section{Evolution Toward Neural Information Retrieval}

Beginning in 2018, Transformer architectures and pretrained models like BERT revolutionized Information Retrieval~\cite{khattab2020,formal2021}. Transformer models acquire deep semantic language representations through large-scale self-supervised pre-training, primarily \textbf{Masked Language Modeling (MLM)}: during training, a random fraction of tokens (typically $15\%$) is masked out with the special token \texttt{[MASK]}, and the network learns to predict the original token via a dense classifier and softmax over the vocabulary $|V|$.

\begin{enumerate}
    \item \textbf{Interaction-Based Models (Cross-Encoders):} The query and document are concatenated into a joint token stream:
    \[
    \text{Input} = \texttt{[CLS]} \circ q \circ \texttt{[SEP]} \circ d
    \]
    and fed together through all self-attention layers. This captures fine-grained cross-token interactions, delivering top-tier ranking quality. However, its high inference cost ($\BigO{|\mathcal{D}| \times \text{Transformer}}$) limits its application to second-stage re-ranking over candidate pools (e.g., top-100 results).
    \item \textbf{Representation-Based Models (Bi-Encoders):} Query and document are encoded independently into vectors. Document embeddings can be indexed offline, reducing online matching to inner products or vector search.
\end{enumerate}

\subsection{Three Embedding Families}
Representation models fall into three broad categories:
\begin{enumerate}
    \item \textbf{Dense Single-Vector (e.g., DPR, Contriever):} Each document and query is mapped to a single dense vector in $\mathbb{R}^d$ ($d \approx 768$), queried via graph-based vector indices (like HNSW).
    \item \textbf{Dense Multi-Vector (e.g., ColBERT~\cite{khattab2020}):} Generates token-level embeddings for query and document tokens, evaluated via \textbf{Late Interaction} using the \textit{MaxSim} operator:
    \begin{equation}
    S(q, d) = \sum_{t_q \in q} \max_{t_d \in d} \left( \vec{E}_{t_q} \cdot \vec{E}_{t_d}^T \right)
    \end{equation}
    Preserves token identity and achieves superior generalization, at the cost of larger index sizes.
    \item \textbf{Sparse Single-Vector (e.g., SPLADE~\cite{formal2021}):} Encodes queries and documents into high-dimensional sparse vectors over the vocabulary $|V|$ ($|V| \approx 30\,000$). Non-zero values represent learned term weights including automated term expansions.
    \begin{itemize}
        \item \textbf{Effectiveness:} High performance across both in-domain and zero-shot out-of-domain evaluation.
        \item \textbf{Efficiency:} Highly compact, directly indexable inside standard Inverted Index structures.
        \item \textbf{Interpretability:} Weights align with human-readable vocabulary words, enabling transparent debugging.
    \end{itemize}
\end{enumerate}

\begin{example}[SPLADE Semantic Expansion]
Consider the natural language query:
\[
q = \text{\texttt{"what shoes do most nba players wear"}}
\]
A learned sparse neural retrieval model (such as SPLADE~\cite{formal2021}) activates a selective subset of vocabulary components over $|V|$, producing a sparse vector with learned weights:
\begin{center}
\small\ttfamily
nba: 2.56, \quad shoes: 2.32, \quad shoe: 2.14, \quad basketball: 1.97, \\
wearing: 1.55, \quad wear: 1.52, \quad most: 1.34, \quad players: 1.25
\end{center}
This example highlights two fundamental advantages of neural sparse models:
\begin{enumerate}
    \item \textbf{Semantic Vocabulary Expansion:} The model autonomously assigns high weight to the term \texttt{"basketball"} ($1.97$) despite its complete absence from the original query text, resolving the classical \textit{vocabulary mismatch} problem.
    \item \textbf{Morphological Harmonization:} It assigns coordinated weights to singular/plural forms (\texttt{shoe} / \texttt{shoes}) and inflected verb variations (\texttt{wear} / \texttt{wearing}), blending the advantages of linguistic stemming with deep contextual learning.
\end{enumerate}
\end{example}

\section{\texorpdfstring{$k$-Approximate Nearest Neighbor Search ($k$-ANN) and Scalability}{k-Approximate Nearest Neighbor Search (k-ANN) and Scalability}}

In high-dimensional embedding spaces, retrieval reduces to finding the top-$k$ documents maximizing the inner product with the query vector (\textit{Maximum Inner Product Search}, MIPS):
\begin{equation}
\operatorname{argmax}_{v \in \mathcal{D}}^{(k)} \; \vec{q}^{\,T} \cdot \vec{v}
\end{equation}

On standard Web-scale collections (e.g., the MS MARCO benchmark):
\begin{itemize}
    \item The document volume exceeds $8.8$ million items ($|\mathcal{D}| \approx 8.8 \times 10^6$).
    \item The vocabulary vector space comprises roughly $30\,000$ dimensions.
    \item Each document activates only approximately $150$ non-zero components on average.
\end{itemize}

\subsection{Forward Index and the TusKANNy Framework}
To avoid the prohibitive latency of exhaustive linear scans, modern sparse $k$-ANN systems combine inverted indices with a \textbf{Forward Index}. In the Forward Index, each document is stored as a compact, contiguous sequence of (component, value) pairs:
\begin{equation}
d_i = \langle (c_1, v_1), (c_2, v_2), \dots, (c_m, v_m) \rangle \quad (\text{with } m \approx 150)
\end{equation}
At query time ($q = \langle (c_1, v_1), \dots, (c_p, v_p) \rangle$), the engine selectively computes inner products only across overlapping non-zero components.

These techniques were highlighted in the international \textbf{NeurIPS'23 Big-ANN Challenge} and the \textbf{SISAP 2026} benchmark. In this ecosystem, \textbf{TusKANNy} (\url{https://tuskanny.com/}) is an open-source, high-performance Rust library co-developed by researchers from ISTI-CNR and the University of Pisa. TusKANNy implements advanced vector pruning and scanning algorithms (such as \textit{Seismic} and \textit{Kannolo}) capable of sustaining over $15\,000$ queries per second (QPS) with recall exceeding $90\%$, operating with sub-millisecond latencies.
